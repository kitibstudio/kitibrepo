═══ HOW TO RUN THE TESTS — GETTING THIS WRONG PASSES SILENTLY ═══
After creating ANY new .swift file you MUST run `xcodegen generate` before
testing. This project uses XcodeGen with classic file references, NOT Xcode
synchronized groups — a new file on disk is NOT in the test target until you
regenerate. A test you wrote but did not regenerate is simply not run, and
the suite exits 0. That looks like success and is not.

  xcodegen generate
  export DEVELOPER_DIR="/Volumes/Samsung 990 2TB/Applications/Xcode.app/Contents/Developer"
  xcodebuild test -project Kitib.xcodeproj -scheme KitibTests \
    -destination 'platform=macOS,arch=arm64'

Never add -quiet: it hides the executed-test count. Always confirm the
"Executed N tests" line shows the number you expect. It is 1 before you start
(the harness smoke test). If N did not go up after you added tests, they are
not wired in — regenerate, do not proceed.
Xcode is on an external volume; if it is unmounted, testing is impossible —
stop and say so rather than skipping the gate.
